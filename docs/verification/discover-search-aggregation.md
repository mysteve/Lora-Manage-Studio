# 在线发现搜索结果缺失修复

日期：2026-09-10。环境：Windows，本地 Rust/Node 工具链；真实公开 civitai.red API，无账号凭据，不读取用户数据或模型目录。

## 原因与改动

公开 API 的关键词搜索先取搜索候选，再应用基础模型等过滤。`frontline + Anima` 的首批只有一个模型，后续批次仍有匹配结果。

- `search_pagination.rs` 统一聚合所有在线模型列表请求，每批取 100 条候选，界面每页最多 24 个模型。保留关键词、基础模型、标签、排序和安全审查参数。
- 空批次继续沿上游游标读取；只有游标耗尽才认为结束。单次最多 8 批、整体 30 秒超时，避免长时间占用。达到批次数上限时保留继续位置，超时或请求失败明确报错，不把失败当作结果耗尽。
- 版本化游标记录上游游标和批内偏移。超过 24 个的批次在下一页重新请求同一上游位置并继续读取，避免截断丢项；无跨搜索共享缓存。网站实时增删数据仍可能造成分页变动，并非固定快照。
- 支持字符串、数字 nextCursor，以及 nextPage URL 中的 cursor。只取参数，实际请求始终发往固定 C 站接口。拒绝重复游标循环和无效列表响应。
- 前端保留既有上一页/下一页和搜索条件变更重置行为；达到读取上限仍有后续结果时给出说明，空批次不再宣称整个搜索无结果。前后端 SearchResult 接口未变，开发预览保持兼容。

## 其他接口检查

基础模型 `/api/v1/enums` 是枚举，模型/版本详情及哈希查询是单项读取，无游标分页。标签 `/api/v1/tags` 实测返回页码元数据，没有 nextCursor；不能把不存在的游标强加给该接口，当前热门标签及关键词查找保持现状。下载、库资料刷新不是远程列表分页，不调整。这里没有全站同步或后台下载操作。

## 本次验证

- `npm test`：18 个文件，60 个测试通过。
- `npm run build`：通过，有现有的大于 500 kB 分块提示。
- `cargo test --manifest-path src-tauri/Cargo.toml`：61 个通过，2 个按设计忽略。新增 5 个离线测试覆盖稀疏/空批次、100 个结果连续翻页及返回第一页、读取预算和续传位置、中途错误、非法响应、重复游标、数字及 URL 游标。
- `cargo test --manifest-path src-tauri/Cargo.toml live_frontline_anima -- --ignored --nocapture`：公开请求、`nsfw=true`，真实运行新聚合器返回 17 个模型，nextCursor 为空；包含模型 1808992、2053356、2033432。耗时约 24 秒。此测试默认忽略，依赖网站和当前模型可用性。
- 同一聚合器使用 `nsfw=false` 实测返回 11 个，已耗尽。最初用该范围断言上述三个模型导致断言失败，说明安全参数确实影响完整结果；随后明确以 `nsfw=true` 验证截图范围，生产实现仍沿用用户安全设置，不自动切换。
- 真实请求曾遇到 C 站 503；实现正常报错，后续重试完成。未承诺远程服务稳定性或两套搜索的排序完全一致。
- `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`：通过。
- 严格 Clippy 被既有 `output_metadata.rs:179` 的 `chunks_exact_to_as_chunks` 告警阻挡。使用 `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings -A clippy::chunks_exact_to_as_chunks` 排除这一条后通过；未修改无关输出模块。
