# 大词库输入性能修复

日期：2026-09-11。

## 原因

PromptInput 在渲染时直接调用 searchTerms，对约 23 万条词条执行同步扫描。每次按键、光标更新和其他片段更新均可能重复扫描，扫描也会发生在没有显示候选的片段中。翻译索引首次创建也位于渲染路径。

## 修改

- 每个词句组合页面共享一个后台搜索 Worker，输入框渲染过程中不再扫描词库。
- 连续输入采用 80ms 防抖，关闭候选、失焦和输入法组合期间取消查询；只展示对应当前查询、分组和词库实例的结果。
- 词库分批复制至 Worker，每批 1000 条，后台创建搜索索引；最近 64 个查询缓存于 Worker。
- 离开页面或更新词库时终止旧 Worker。初始化期间只派发尚未取消的查询，过期响应被丢弃。
- 中文翻译索引每批 2000 条准备，完成后才发布词库状态。翻译组件使用 memo/useMemo，未修改片段不重复计算。
- 保留中英文、别名和模糊匹配、正负向筛选、键盘选择、逗号及空格插入。

## 实际验证

环境：Windows 上的 Codex 内置 Chromium 浏览器，Vite 开发预览，完整词库及独立 preview 数据。临时采样页位于被忽略的 `.test-data/prompt-input-performance.html`，导入实际应用代码；在捕获 input 事件时记录时间，下一次 requestAnimationFrame 记录完成时间，PerformanceObserver 记录主线程 longtask。

三个片段同时存在、后台完整词库就绪后，逐键输入 80 次：

- input 到下一帧最大延迟：17.2 ms。
- 第 95 百分位延迟：15.6 ms。
- 采样区间内超过 50 ms 的主线程 longtask：0 次。

这项测量不等于标准 INP，也不代表搜索结果会在 17.2 ms 内返回；建议列表包含防抖及后台查询时间。首次页面加载、低配置设备和真实 Tauri WebView2 未进行同口径性能采样。

浏览器另外验证：完整词库能返回 1girl；中文柔光补全后插入 soft lighting 加逗号及空格且光标位置正确；Esc 关闭候选；负向模糊查询正常；控制台 error/warn 为空。

- `npm test`：23 个测试文件，81 项通过。
- 新增 Worker 客户端测试：分批传输、初始化时取消过期查询、丢弃在途旧响应和终止清理。
- `npm run build`：通过，后台搜索脚本独立输出约 4.01 kB；原有大词库分包大小提示保留。
- `git diff --check`：通过。
